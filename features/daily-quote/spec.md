# 需求规格：「每日一句」双端展示系统

> 需求ID：daily-quote ｜ 阶段：clarify ｜ 状态：⏳ 待人工审查（门禁未过不得进入下一阶段）
> 输入：requirement.md、business.md、data-model.md、flows.md、宪法 v1.1
> 说明：本规格只描述「做什么、给谁做、边界在哪」，不含技术实现细节。

## 1. 需求背景与目标

### 1.1 背景
「每日一句」是轻量内容展示产品：每天为读者展示一段选自易引发共鸣的文学作品的引人深思的句子（如《自渡》中的「人生自苦，他人难悟，唯有自爱，方能自渡」），配一张清新风格背景图，以精致排版呈现。读者通过微信小程序与 Web 两端阅读；内容由运营方预先准备（语料与配图以测试数据预置入库），按展示日期自动上架。

### 1.2 目标
- 读者在任一端都能查看当日唯一语录，双端内容一致。
- 内容按展示日期自动上架，全程无人工操作。
- 任何情况下不白屏：当日无内容展示兜底内容；接口不可用展示本地兜底文案。

## 2. 角色与端

| 角色 | 使用端 | 核心动作与权限 |
|---|---|---|
| 读者 | 微信小程序、Web 展示页 | 查看当日语录（只读、匿名、无账号） |
| 运营者 | MVP 阶段不经系统操作 | 语料与配图以测试数据预置入库 |

合规说明：小程序端不收集任何个人信息（无登录、无用户标识）；如未来引入收集，须按宪法第六条完成隐私声明。

## 3. 功能需求

### Req-1 当日语录展示（双端）
**EARS**：WHEN 读者访问「每日一句」展示页，THEN 系统 SHALL 按 Asia/Shanghai 时区当前日期返回并展示当日唯一一条已上架语录，包含语录正文、出处、一张背景图及当天日期。
**端边界**：
- 后端：按 Asia/Shanghai 时区当前日期返回当日已上架语录内容与背景图。
- 小程序：以精致排版呈现背景图、语录正文、出处、当天日期四要素。
- Web 展示页：独立展示页（纯展示，无管理界面），通过后端静态页面路由访问；以精致排版呈现相同四要素，背景图采用同一张图居中裁切适配宽屏。
**验收标准**：
- AC1.1：当日存在已上架语录时，两端均展示该语录正文、出处、背景图，内容与预置数据逐字一致。
- AC1.2：同一天两端展示内容完全一致（同一条语录）。
- AC1.3：「精致排版」的可测断言：背景图、正文、出处、当天日期四要素齐全，文字完整可读、无缺失；风格由运营预置把关。
- AC1.4：语录正文展示不超过 60 字；若正文超过 60 字，则截断正文并保留出处完整。
- AC1.5：背景图单图 ≤ 500KB，竖屏优先；Web 端用同一张图居中裁切适配宽屏。

### Req-2 按日期自动上架（后端）
**EARS**：THE 系统 SHALL 在语录的预置展示日期当天自动使其对读者可见，无需任何人工发布操作。
**事件响应**：WHEN Asia/Shanghai 时区当前日期等于某语录的展示日期且该语录状态为已上架，THEN 系统 SHALL 将该语录作为当日内容返回；日期切换点为 Asia/Shanghai 时区每日 0 点整。
**验收标准**：
- AC2.1：预置展示日期为 D、状态已上架的语录，D 日当天可被读者看到，全程零人工操作。
- AC2.2：展示日期 D 的前一天，该语录对读者不可见。
- AC2.3：展示日期 D 过后，该语录不再作为「今日语录」返回。

### Req-3 当日唯一性（后端）
**EARS**：THE 系统 SHALL 保证每个展示日期最多只有一条已上架语录。
**非期望行为**：IF 预置数据使同一展示日期出现两条及以上已上架语录，THEN 系统 SHALL 拒绝重复并给出报错提示。
**验收标准**：
- AC3.1：同一日期重复预置（均为已上架）被系统拦截，并给出明确报错。
- AC3.2：任意日期查询，返回的已上架语录至多一条。
- 边界：同一语录正文允许在不同展示日期复用；唯一性约束按「日期」而非「语录」执行。

### Req-4 当日无内容时兜底（双端）
**EARS**：IF 当前日期没有已上架语录，THEN 系统 SHALL 返回预置兜底内容（一条默认语录 + 一张默认背景图），SHALL NOT 返回空内容导致白屏。
**端边界**：后端判断当日无内容并返回兜底内容；两端按正常内容同样渲染。
**验收标准**：
- AC4.1：当日无已上架语录时，接口返回兜底内容，两端正常展示。
- AC4.2：兜底内容正文、出处非空，且带背景图。
- AC4.3：「当日有内容」「当日无内容」两种情形下，读者均看到完整展示页（无白屏、无报错页）。

### Req-5 接口不可用时前端降级（双端）
**EARS**：IF 后端接口不可用（请求失败或超时），THEN 前端 SHALL 展示预置的本地兜底文案，确保不白屏。
**端边界**：小程序与 Web 展示页各自预置一份本地兜底文案，独立降级。
**验收标准**：
- AC5.1：接口不可用时，小程序展示本地兜底文案，页面完整、不白屏。
- AC5.2：接口不可用时，Web 展示页展示本地兜底文案，页面完整、不白屏。
- AC5.3：本地兜底文案至少含语录正文与出处，内容非空。

### Req-6 免登录匿名访问（双端）
**EARS**：THE 系统 SHALL 允许读者在无任何登录或注册的情况下查看每日语录；读者端 SHALL NOT 提供任何账号入口。
**端边界**：两端均直接打开即看，不索取登录态、不采集账号信息。
**验收标准**：
- AC6.1：未登录状态下，两端均可直接打开并查看当日语录。
- AC6.2：两端均无登录、注册、账号管理入口。
- AC6.3：查看语录的请求不携带、不校验登录态；该公开接口需列入接口鉴权白名单（宪法 2.2）。

### Req-7 内容稳定与可追溯（后端）
**EARS**：THE 系统 SHALL NOT 静默变更已上架语录内容；任何内容变更 SHALL 可追溯。
**验收标准**：
- AC7.1：系统不存在对已上架语录内容的无记录静默修改途径。
- AC7.2：已上架内容发生变更时，可通过数据记录（如变更时间标记）核实。

### Req-8 内容格式与来源合规（后端）
**EARS**：THE 系统 SHALL 保证展示给读者的每条语录正文非空、出处非空，且出处格式统一为「《书名》—— 作者」。
**非期望行为**：IF 预置数据正文或出处为空、出处格式不符，THEN 系统 SHALL 在预置阶段拒绝该条数据。
**验收标准**：
- AC8.1：所有预置语录正文非空且 ≤ 60 字，出处非空，出处符合「《书名》—— 作者」格式。
- AC8.2：不符合格式要求的数据无法进入可上架状态。
- AC8.3：预置语料选用公版作品或短摘录，均注明来源（书名+作者）。
- AC8.4：预置背景图单图 ≤ 500KB，在两端均可正常加载显示，不出现图片缺失。

## 4. 不做什么（范围边界）

- 不做登录、注册、账号体系，读者全程匿名查看。
- 不做后台管理界面，内容仅以测试数据预置入库，本期无任何运营操作界面。
- 不做历史浏览、浏览记录、阅读统计。
- 不做读者端互动：无点赞、收藏、评论、分享功能。
- 不做个性化推荐或差异化内容分发，所有读者在两端看到同一条当日语录。
- 不做多语言、翻译、音频、视频等衍生内容形态，内容形态仅为「文字 + 一张背景图」。
- 不收集任何个人信息（无登录、无用户标识）。
- 不做访问限流/防刷（MVP 阶段）。

## 5. 澄清结论

| # | 决策 |
|---|---|
| 5.1 | 以 Asia/Shanghai 时区为准，每日 0 点整切换 |
| 5.2 | Web 展示页为独立展示页（纯展示，无管理界面），访问入口为后端静态页面路由 |
| 5.3 | 语录正文单条 ≤ 60 字；超出时截断显示并保留出处完整 |
| 5.4 | 背景图单图 ≤ 500KB，竖屏优先；Web 端用同一张图居中裁切适配宽屏 |
| 5.5 | 每日语录查询接口列入鉴权白名单；MVP 不做限流防刷 |
| 5.6 | 同一语录正文允许在不同展示日期复用；唯一性约束按「日期」而非「语录」 |
| 5.7 | 展示当天日期（Asia/Shanghai 日期） |
| 5.8 | 接口响应时间目标 P95 ≤ 500ms |
