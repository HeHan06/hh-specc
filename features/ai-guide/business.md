# 业务层知识：ai-guide

## 1. 业务背景

AI Agent 方向岗位的候选人（社招为主，兼顾 1–5 年经验）在备考时，最缺的不是信息量，而是把零散的一手面试经验与知识体系整合成可系统备考、可持续更新的指南。当前一手面经、题目复盘、知识总结分散在不同来源，难以按面试主题快速定位，也难以复用标准答案与教训。

本平台以 Web 阅读站 + Web 管理后台两个端交付：阅读站面向候选人，提供「主题 → 专题 → 内容」三级内容组织、搜索、点赞、打赏与付费咨询；管理后台由单一管理员维护内容、处理订单。

变现方式锁定为打赏 + 付费咨询，明确不做订阅。

## 2. 领域术语表

| 术语 | 业务含义 |
|---|---|
| AI Agent 方向岗位 | 覆盖 Agent 架构与设计、工具调用/Tool、规划与多 Agent、上下文与记忆、LLM 基础、常见 Agent 框架等方向岗位 |
| 一手面试经验 | 真实面试记录/复盘，含题目、追问、当时回答、事后标准答案与教训 |
| 知识体系 | 按「主题 → 专题 → 文章/题目」三级组织的系统化备考内容 |
| 主题（Topic） | 内容的一级分类，如 Agent 设计、大模型基础、后端基础、算法题、面试记录、简历优化 |
| 专题（Category） | 内容在主题下的二级分类，如某个知识点、某家公司或某个细分场景 |
| 内容（Content） | 阅读站的最小内容单元，分四类：文章、面试复盘、题目、简历优化内容 |
| 文章 | 系统化知识讲解类内容 |
| 面试复盘 | 一手面试记录与经验教训类内容 |
| 题目 | 面试题、算法题或 SQL 题及思路/答案类内容 |
| 简历优化内容 | 简历模板、自查清单、高频问题文章等内容 |
| 访客 | 阅读站的匿名使用者；阅读/搜索/点赞/打赏无需登录，付费咨询需留联系方式 |
| 管理员 | 管理后台唯一账号，负责内容录入、审核发布与订单处理 |
| 点赞 | 访客对内容表达的匿名支持，同一访客同一内容只计一次 |
| 打赏 | 访客对内容表达的自定义金额支持，非订阅 |
| 付费咨询 | 访客留下联系方式、咨询主题与期望时间并支付后，由管理员确认排期的一对一辅导服务 |
| 发布 | 内容经人工审核后对访客可见的动作 |
| 下架 | 已发布内容撤下，不再对访客可见 |
| 归档 | 内容进入保留终态，不再展示、不自动删除 |

## 3. 角色模型

| 角色 | 使用端 | 职责与边界 |
|---|---|---|
| 访客（匿名） | Web 阅读站 | 浏览目录、搜索、阅读内容、点赞、打赏、发起付费咨询；无角色分级 |
| 管理员（单一账号） | Web 管理后台 | 登录后台；维护主题/专题/内容；发布前人工审核；处理打赏/咨询订单；执行收款确认、状态变更等敏感操作 |

### 3.1 身份边界（已锁定）

- 阅读 / 搜索 / 点赞：匿名可用，无角色差异。
- 打赏：匿名可用，联系方式可选。
- 付费咨询：必须留下手机/微信联系方式，通过加管理员微信完成线下收款。
- 管理后台：仅单一管理员账号可登录。

## 4. 内容组织与来源

- 组织层级：主题 → 专题 → 内容（文章 / 面试复盘 / 题目 / 简历优化内容）。
- 内容来源：首批内容由管理员从现有知识库与一手面试记录中人工迁移/录入；后续由管理员新增/更新。
- 平台不开放投稿与用户生成内容。

## 5. 业务红线

- 所有内容发布前必须人工审核，未审核通过的内容不得在阅读站可见。
- 不做订阅；不做内推、求职匹配、招聘岗位/企业职位列表。
- 不开放用户公开社区、发帖、评论，降低 UGC 合规与审核成本。
- 不收集用户级浏览行为；仅统计内容浏览数与站点 PV 等聚合指标。
- 隐私遵循最小必要原则：付费咨询仅收集必要联系方式。
- 订单按平台要求留存；敏感操作（内容删除、订单收款确认、状态变更）仅管理员可执行并记录操作日志。
- 不引入 AI 模型能力，不做模拟面试/自动批改。
