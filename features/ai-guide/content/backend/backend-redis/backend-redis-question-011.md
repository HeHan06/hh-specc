## 问题

Redis 锁过期时间怎么设置。

## 考察点

- 不同业务场景下锁 TTL 的设置策略
- 看门狗续期与手动短 TTL 的取舍

## 标准答案

这个问题要分场景看：

### 耗时不确定、性能不敏感的后台异步任务

使用 lock() 无参方法，依赖默认 30 秒 + 看门狗自动续期，确保业务执行完整。

### 高并发、短耗时的核心接口（如扣库存）

主动禁用看门狗，手动设置一个基于业务 P99 耗时估算的短 TTL（如 500ms）。这有三点考量：

1. 避免看门狗带来的额外 Redis 网络开销。
2. 强制业务在 SLA 内完成，超过即熔断。
3. 防止 GC 停顿导致看门狗续期失败带来的数据风险。
