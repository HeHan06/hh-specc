## 问题

Redis 为什么这么快且高并发。

## 考察点

- 纯内存、IO 多路复用、单线程无锁三大原因
- Redis 6.0 多线程的边界

## 标准答案

- 纯内存操作：数据在内存，省去磁盘寻道时间，这是量级优势。
- IO 多路复用（epoll）：让单线程能监听海量 Socket 连接，支撑高并发 TCP 连接数。
- 单线程命令执行 + 无锁设计：规避了多线程频繁的上下文切换和锁竞争开销，将 CPU 资源全部投入到内存数据处理上；6.0 后的多线程仅用于辅助网络 IO 的读写，不参与命令运算。
