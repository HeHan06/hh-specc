# 需求探询沉淀：ai-guide

> 本文件为 probe 阶段九维需求沉淀。【必填】=用户回答，【协作】=用户直觉，【方案】=AI 草案（待确认或改）。
> 一句话复述（用户已确认）：面向 AI Agent 方向岗位候选人的面试指南 Web 平台，以一手面试经验与系统化知识体系为核心内容，变现方式为打赏与付费咨询。

## 1. 产品定位【必填】

- 目标用户：正在准备 AI Agent 方向岗位的候选人（社招为主，兼顾 1–5 年经验）
- 核心问题：把零散的一手面经 + 知识体系整合成可系统备考、可持续更新的指南
- 成功标志（可衡量）：**访问量 3 个月 > 3k**（按站点页面浏览次数 PV 统计，上线后连续 3 个月累计 PV > 3000，月均 ≥ 1000）

## 2. 端与角色【必填】

- 端：仅 Web 管理后台 + 面向用户的 Web 阅读站（两个 Web 端）
- 用户侧角色：**暂时无需区分用户角色**（所有用户同等访问内容）
- 管理侧角色：**暂时无需设置管理侧角色**（单一后台账号即可）

## 3. 核心流程【方案】

> 草案，请确认或改。

- 主流程（用户侧，全部内容无订阅门槛）
  1. 访客进入 Web 阅读站首页，看到「主题 → 专题」目录与最新/推荐内容
  2. 通过目录或搜索进入专题，再进入「文章 / 面试复盘 / 题目 / 简历优化内容」
  3. 阅读内容；内容页可「点赞」，可通过「打赏」表达支持
  4. 需要深度辅导时发起「付费咨询」：填写最低必要联系信息、咨询主题与期望时间 → 按次/按时长计价并支付 → 管理员确认排期
- 管理主流程（单一后台账号）
  1. 管理员登录 Web 管理后台
  2. 创建/编辑/发布/下架「主题、专题、内容」
  3. 查看并处理「打赏订单、咨询订单」：确认排期、标记完成或取消
- 关键分支
  - 未登录/登录：阅读、搜索、点赞无角色差异；点赞/打赏/咨询的身份与鉴权边界见第 6 节
  - 首次访问：首页目录引导；重复访问：用搜索/目录直达内容，无收藏/学习进度等个性化状态
  - 收款确认：管理员在后台确认收款/排期后流转订单状态，不产生权益前不阻断阅读

## 4. 数据对象【方案】

> 草案，请确认或改。以下为最小核心实体，字段与契约细节留到 specify/plan 再定。

- 主题（Topic）：主题编码、名称、简介、排序、状态（启用/停用）
- 专题（Category）：专题编码、所属主题、名称、简介、排序、状态
- 内容（Content）：内容编码、所属专题、类型（文章/面试复盘/题目/简历优化内容）、标题、摘要、正文（Markdown）、标签、来源（原创/迁移）、状态（草稿/已发布/已归档）、点赞数、浏览数、发布时间、更新时间
- 点赞（Like）：内容编码、访客标识（匿名，如设备号）、创建时间；同一访客同一内容仅一条
- 打赏订单（TipOrder）：订单号、关联内容（可空）、金额、打赏人联系信息（可选）、留言、状态（已提交/已收款/已关闭）、创建时间、收款时间
- 咨询订单（ConsultationOrder）：订单号、联系人、联系方式（手机/微信）、咨询主题、咨询诉求、计价方式（500 元/半小时）、金额、期望时间、状态（已提交/已确认/已完成/已取消）、管理员备注、创建时间
- 管理员（AdminUser）：账号、密码哈希、固定单一管理员角色
- 生命周期
  - 内容：管理员创建草稿 → 编辑 → 发布；可更新/下架/归档，不自动删除
  - 点赞：访客点击新增，重复点击仅忽略
  - 打赏：创建留资单 → 加管理员微信付款 → 管理员确认收款
  - 咨询：提交订单 → 加管理员微信付款 → 管理员确认排期 → 完成/取消

## 5. 边界规则【方案】

> 草案，请确认或改。

- 空数据：目录/列表/搜索无结果给出空态提示；内容不存在返回 404 与统一错误码
- 输入非法：分页大小、搜索词长度、金额、联系方式均做类型与边界校验；后端统一异常响应，前端统一拦截提示，不静默吞错
- 权限不足：管理后台仅单一账号可登录，登录失败/越权返回统一错误；用户侧无角色差异
- 重复点赞：同一访客同一内容只计一次，后端幂等处理
- 并发冲突：内容编辑采用乐观锁（更新时校验更新时间/版本），冲突时提示重新加载
- 金额与状态：打赏金额固定枚举，咨询金额 500 元/半小时；非法金额拒绝；订单状态变更记录日志
- 依赖不可用：搜索降级为数据库/应用层查询兜底；收款依赖管理员人工操作，后台清晰展示留资信息避免漏单
- 敏感操作：内容删除、订单收款确认、状态变更仅管理员可操作并记录操作日志
- 性能兜底：列表/详情/搜索满足第 8 节约定 P95；超时返回可重试错误，前端展示加载失败与重试入口

## 6. 假设与依赖【方案】

> 草案，请确认或改。

- 内容来源：首批内容由单一后台账号从现有知识库与一手面试记录中人工迁移/录入；后续由管理员新增/更新，暂不开放投稿与用户生成内容
- 账号体系：用户侧暂不建完整账号/角色体系。身份边界已锁定：**阅读/搜索/点赞匿名可用；打赏匿名可用（联系方式可选）；付费咨询必须留手机/微信，通过加管理员微信完成线下收款**
- 收款方式：不接入在线支付（无商户资质），打赏与付费咨询统一「加管理员微信」线下收款，管理员微信号由后台配置并下发阅读站展示
- 内容合规：所有内容发布前人工审核；不接入爬虫、不开放评论/社区，降低 UGC 合规与审核成本
- 隐私与安全：遵循最小必要原则，不收集用户浏览行为；订单按平台要求留存，管理员密码哈希存储
- 外部环境：依赖部署域名、HTTPS 证书、数据库备份、监控告警等常规基础设施（plan/implement 阶段落实）
- 技术边界：不引入 AI 模型能力（不做模拟面试/自动批改）；搜索实现方案（PostgreSQL 全文检索或应用层搜索）留到 plan 阶段决定

## 7. 领域术语【协作】

- 「AI Agent 方向岗位」覆盖范围：Agent 架构与设计、工具调用/Tool、规划与多 Agent、上下文与记忆、LLM 基础、常见 Agent 框架
- 「一手面试经验」：真实面试记录/复盘（含题目、追问、当时回答、事后标准答案与教训）
- 「知识体系」形态：按「主题 → 专题 → 文章/题目」三级组织，支持目录与搜索
- 「付费边界」：**不做订阅**，付费仅打赏 + 付费咨询

## 8. 量化约束【协作】

- 内容规模：上线首批 ≥ 20 篇核心内容；此后每月新增/更新 ≥ 4 篇
- 访问规模：**每月 ≥ 1000 PV**（连续 3 个月累计 PV > 3000，不做订阅，无订阅用户规模指标），不追求并发规模
- 性能与可用性：用户端首屏 < 3s；列表/详情接口 P95 < 500ms；搜索接口 P95 < 1s；内容页可读性优先于交互特效
- 付费定价：不做订阅商品；付费咨询按次/按时长计价，打赏金额用户自定；具体价格留到 plan 阶段再定

## 9. 明确不做【必填】

- 做：简历优化（内容专区：简历模板/自查清单/高频问题文章 + 付费一对一咨询中可选简历辅导）、付费一对一咨询、点赞
- 不做：订阅（订阅商品/订阅订单/订阅权益）、内推、求职匹配、招聘岗位/企业职位列表、用户公开社区/发帖/评论、收藏、学习进度、AI 模拟面试/自动答题批改、App
