# 需求规格：ai-guide

## 0. 背景与目标

面向正在准备 AI Agent 方向岗位的候选人（社招为主，兼顾 1–5 年经验），把零散的一手面试经验与知识体系整合成可系统备考、可持续更新的 Web 阅读平台。平台由「Web 阅读站 + Web 管理后台」两个 Web 端组成：访客可浏览、搜索、阅读、点赞、打赏并发起付费咨询；单一管理员负责内容录入、审核发布与订单处理。变现方式为打赏 + 付费咨询，明确不做订阅。

成功标志：上线后连续 3 个月累计 PV > 3000，且月均 ≥ 1000；首批核心内容 ≥ 20 篇，此后每月新增/更新 ≥ 4 篇。

## 1. 角色与权限

| 角色 | 使用端 | 在本需求中能做什么 |
|---|---|---|
| 访客（匿名） | Web 阅读站 | 浏览目录、搜索、阅读内容、点赞、打赏、发起付费咨询；无角色分级 |
| 管理员（单一账号） | Web 管理后台 | 登录后台；维护主题/专题/内容；发布前人工审核；处理打赏/咨询订单；执行收款确认、状态变更等敏感操作 |

身份边界：阅读/搜索/点赞匿名可用；打赏匿名可用且联系方式可选；付费咨询必须留下手机/微信联系方式；打赏与付费咨询均通过加管理员微信（微信号由后台配置）完成线下收款，不接入在线支付；管理后台仅单一管理员账号可登录。

## 2. 功能需求

### Req-1：内容目录浏览 【端归属：阅读站】

系统 SHALL 向访客提供按「主题 → 专题」组织的目录，并展示最新与推荐内容。

- WHEN 访客进入首页 THEN 展示主题/专题目录与最新、推荐内容。
- WHEN 访客进入某专题 THEN 展示该专题下的内容列表，列表项包含标题、摘要、更新时间。
- IF 目录或列表无数据 THEN 显示明确空态提示，不显示空白页。

**验收标准：**
- [ ] AC-1.1：首页可见主题与专题目录，以及「最新/推荐」内容入口。
- [ ] AC-1.2：进入任一专题可看到该专题下的内容列表，且列表项含标题、摘要、更新时间。
- [ ] AC-1.3：空专题/空列表显示明确空态文案，而非空白页面。

### Req-2：内容搜索 【端归属：阅读站】

系统 SHALL 提供内容搜索能力，支持按标题、摘要、标签检索已发布内容。

- WHEN 访客输入关键词并提交 THEN 展示匹配的已发布内容列表。
- IF 无匹配结果 THEN 显示无结果空态。
- IF 搜索词非法或超长 THEN 返回统一校验错误并提示合法输入。
- IF 搜索能力不可用 THEN 降级为兜底查询，仍返回结果或提示重试，不静默失败。

**验收标准：**
- [ ] AC-2.1：搜索可命中标题、摘要、标签中的关键词。
- [ ] AC-2.2：搜索结果只包含「已发布」内容，不含草稿、已归档内容。
- [ ] AC-2.3：无结果时显示无结果空态。
- [ ] AC-2.4：搜索响应 P95 < 1000ms。

### Req-3：内容阅读 【端归属：阅读站】

系统 SHALL 展示内容详情，包括标题、摘要、正文、标签、来源、发布时间、更新时间、点赞数与浏览数；正文为结构化 Markdown，分节骨架与渲染规范见 Req-14。

- WHEN 访客打开已发布内容 THEN 展示完整内容与上述元信息，并对该内容累计一次浏览数。
- IF 内容不存在、为草稿或已归档 THEN 返回统一「内容不存在」提示，不暴露后台状态。
- IF 内容不可读 THEN 展示加载失败与重试入口，不静默吞错。

**验收标准：**
- [ ] AC-3.1：已发布内容可见完整正文与元信息。
- [ ] AC-3.2：不存在/草稿/已归档内容返回统一「内容不存在」提示。
- [ ] AC-3.3：每次有效阅读后内容浏览数增加 1，且不采集用户级浏览行为。
- [ ] AC-3.4：详情响应 P95 < 500ms。

### Req-4：点赞 【端归属：阅读站】

系统 SHALL 允许访客对内容点赞，同一访客同一内容至多保留一条点赞记录，重复操作不重复计数。

- WHEN 访客对内容点赞 THEN 点赞数增加 1，并记录访客标识与内容标识。
- IF 同一访客再次对同一内容点赞 THEN 系统幂等处理，不产生重复记录、不重复计数。
- IF 并发/重复提交 THEN 后端幂等，结果仍只计一次。

**验收标准：**
- [ ] AC-4.1：首次点赞后内容点赞数增加 1。
- [ ] AC-4.2：同一访客同一内容重复点赞不产生重复计数。
- [ ] AC-4.3：点赞的唯一性约束为「同一访客同一内容 ≤ 1 条」。
- [ ] AC-4.4：重复点击的具体交互为「仅忽略」——不取消点赞、不重复计数、不产生任何反馈干扰。

### Req-5：打赏 【端归属：阅读站】

系统 SHALL 允许访客对内容打赏，金额由访客从系统预设枚举中选择，联系方式可选，并生成打赏留资单；访客通过加管理员微信完成线下支付。

- WHEN 访客选择合法金额档位并发起打赏 THEN 创建打赏留资单，并展示管理员微信号与「备注订单号完成支付」的提示。
- IF 金额不在预设枚举内 THEN 拒绝并提示合法金额档位。
- IF 联系方式缺失 THEN 不影响打赏留资（联系方式为可选）。
- IF 访客提交打赏 THEN 留言内容按隐私保密处理，仅管理员可见。

**验收标准：**
- [ ] AC-5.1：打赏后生成打赏留资单，记录关联内容、金额与状态。
- [ ] AC-5.2：非法金额（非枚举档位）被拒绝，并提示合法金额档位。
- [ ] AC-5.3：联系方式为可选，缺省不影响打赏留资。
- [ ] AC-5.4：打赏金额为固定枚举：0.1 / 1 / 5 / 10 / 50 / 100 元。
- [ ] AC-5.5：提交后展示管理员微信号与「备注订单号完成支付」提示。

### Req-6：付费咨询 【端归属：阅读站】

系统 SHALL 允许访客发起付费咨询，必须填写联系人、联系方式（手机/微信）、咨询主题、咨询诉求与期望时间；计价为 500 元/半小时，通过加管理员微信完成线下支付。

- WHEN 访客提交合法咨询信息 THEN 创建咨询订单，订单进入待管理员确认排期，并展示管理员微信号与「备注订单号完成支付」的提示。
- IF 联系方式缺失或格式非法 THEN 拒绝提交并提示。
- IF 访客提交咨询 THEN 咨询诉求与留言按隐私保密处理，仅管理员可见。
- IF 访客留资后未加微信完成支付 THEN 管理员不确认排期。

**验收标准：**
- [ ] AC-6.1：咨询订单包含联系人、联系方式、咨询主题、咨询诉求、期望时间、计价方式与金额。
- [ ] AC-6.2：联系方式必填且通过格式校验。
- [ ] AC-6.3：未完成线下支付的订单不确认排期。
- [ ] AC-6.4：计价为 500 元/半小时；全平台前 10 个经管理员确认排期的咨询订单免费（按确认时间先后占用名额）。
- [ ] AC-6.5：提交后展示管理员微信号与「备注订单号完成支付」提示。

### Req-7：订单状态流转 【端归属：阅读站】

系统 SHALL 对打赏订单与咨询订单维护线下收款状态，由管理员在后台确认收款后流转订单状态。

- WHEN 管理员确认打赏已收款 THEN 打赏订单置为已收款并记录收款时间。
- WHEN 管理员确认咨询排期 THEN 咨询订单置为已确认，并按确认时间先后占用免费名额（前 10 个确认订单免费）。
- IF 管理员关闭打赏订单 THEN 订单置为已关闭。
- IF 管理员取消咨询 THEN 订单置为已取消。

**验收标准：**
- [ ] AC-7.1：管理员确认收款后，打赏订单状态为已收款并记录收款时间。
- [ ] AC-7.2：管理员确认排期后，咨询订单状态为已确认。
- [ ] AC-7.3：状态流转遵循状态机约束，非法流转被拒绝。
- [ ] AC-7.4：打赏订单支持已关闭状态，咨询订单支持已取消状态。

### Req-8：管理后台登录与权限 【端归属：管理后台】

系统 SHALL 仅允许单一管理员账号登录管理后台，并对后台功能进行权限校验。

- WHEN 管理员输入正确凭据 THEN 进入管理后台。
- IF 凭据错误 THEN 返回统一登录失败提示，不泄露账号是否存在。
- IF 未登录或越权访问后台功能 THEN 拒绝访问并返回统一错误。

**验收标准：**
- [ ] AC-8.1：仅配置的唯一管理员账号可登录后台。
- [ ] AC-8.2：登录失败给出统一提示，不区分「账号不存在/密码错误」。
- [ ] AC-8.3：未登录或越权访问后台功能被拒绝并返回统一错误。

### Req-9：内容与目录管理 【端归属：管理后台】

系统 SHALL 允许管理员创建、编辑、发布、下架、归档主题、专题与内容，并维护内容类型、标签、来源、排序与状态。

- WHEN 管理员创建或编辑内容 THEN 可保存为草稿或发布。
- WHEN 管理员更新内容 THEN 系统校验更新时间/版本，检测并发冲突。
- WHEN 管理员下架已发布内容 THEN 内容进入独立的「已下架」状态，可恢复发布或归档，而非退回草稿。
- IF 编辑发生并发冲突 THEN 提示重新加载，不静默覆盖。
- IF 内容不存在 THEN 返回统一错误。

**验收标准：**
- [ ] AC-9.1：管理员可维护主题、专题、内容的完整生命周期。
- [ ] AC-9.2：内容状态可在草稿/已发布/已下架/已归档间合法流转，且不自动删除；「下架」为独立状态，不退回草稿。
- [ ] AC-9.3：并发编辑冲突被检出并提示重新加载，不静默覆盖。
- [ ] AC-9.4：内容类型固定为文章、面试复盘、题目、简历优化内容四类。

### Req-10：发布前人工审核 【端归属：管理后台】

系统 SHALL 在内容发布前要求完成人工审核，仅审核通过的内容对访客可见。

- WHEN 管理员发布内容 THEN 必须完成发布前人工审核确认。
- IF 内容未通过发布审核 THEN 不得出现在阅读站目录、搜索与详情中。

**验收标准：**
- [ ] AC-10.1：发布流程包含明确的人工审核步骤。
- [ ] AC-10.2：未通过审核的内容不可见，通过后才对访客可见。
- [ ] AC-10.3：已发布内容可下架，下架后对访客不可见。

### Req-11：订单管理 【端归属：管理后台】

系统 SHALL 允许管理员查看打赏订单与咨询订单，并对咨询订单确认排期（含免费名额判定）、标记完成或取消，对打赏订单标记已收款或关闭。

- WHEN 管理员确认咨询排期 THEN 咨询订单状态更新为已确认，并按确认时间先后占用免费名额（前 10 个确认订单免费）。
- WHEN 管理员标记完成或取消 THEN 订单状态相应更新。
- WHEN 管理员确认打赏已收款或关闭 THEN 打赏订单状态相应更新。
- IF 管理员执行收款确认、取消、状态变更等敏感操作 THEN 记录操作者、时间、对象、动作。

**验收标准：**
- [ ] AC-11.1：管理员可查看打赏订单与咨询订单的列表及详情。
- [ ] AC-11.2：管理员可确认排期、标记完成、取消咨询订单。
- [ ] AC-11.3：管理员可对打赏订单标记已收款或关闭。
- [ ] AC-11.4：收款确认、取消、状态变更等敏感操作均留有操作日志。

### Req-12：输入校验与错误反馈 【端归属：阅读站 + 管理后台】

系统 SHALL 对分页大小、搜索词长度、金额、联系方式等所有入参进行类型与边界校验，并以统一错误反馈，不静默吞错。

- IF 入参非法 THEN 返回统一校验错误并提示合法输入。
- IF 内容不存在或权限不足 THEN 返回统一错误。
- IF 请求失败或超时 THEN 前端展示加载失败与重试入口。

**验收标准：**
- [ ] AC-12.1：非法分页大小、超长搜索词、非法金额、非法联系方式均被拒绝。
- [ ] AC-12.2：用户看到统一错误提示与重试入口，而非空白或静默失败。
- [ ] AC-12.3：内容不存在、权限不足有统一错误反馈。

### Req-13：性能与可用性 【端归属：阅读站 + 管理后台】

系统 SHALL 满足阅读站与后台的性能目标，并在失败或超时场景提供可重试反馈。

- WHEN 访客打开阅读站首屏 THEN 首屏渲染时间 < 3s。
- IF 请求失败或超时 THEN 展示加载失败与重试入口。

**验收标准：**
- [ ] AC-13.1：阅读站首屏 < 3000ms。
- [ ] AC-13.2：列表/详情响应 P95 < 500ms。
- [ ] AC-13.3：搜索响应 P95 < 1000ms。
- [ ] AC-13.4：失败/超时展示加载失败与重试入口。

### Req-14：内容结构化与 Markdown 渲染 【端归属：阅读站 + 管理后台】

系统 SHALL 将内容正文统一为结构化 Markdown，四类内容各遵循固定分节骨架（唯一真相源 `content-template.md`），并在阅读站以富文本渲染展示。

- WHEN 管理员录入或导入内容 THEN 正文遵循 `content-template.md` 中对应类型的固定分节骨架。
- WHEN 访客打开内容详情 THEN 阅读站以 Markdown 渲染正文，展示标题、加粗、列表、代码块等视觉层级。
- WHEN 内容为 question 类型 THEN 正文包含「问题 / 考察点 / 标准答案 / 关联」固定分节。
- WHEN 内容为 interview 类型 THEN 正文包含「面试概览 / 面试问题与回答 / 复盘总结」固定分节。
- WHEN 内容为 article 类型 THEN 正文包含「概述 / 正文 / 总结」固定分节。
- WHEN 内容为 resume 类型 THEN 正文包含「简历正文 / 优化说明」固定分节。
- IF 正文为非结构化纯文本 THEN 不得作为新发布内容入库；存量纯文本内容按幂等脚本迁移为结构化 Markdown。

**验收标准：**
- [ ] AC-14.1：正文以 Markdown 存储，阅读站渲染出标题、加粗、列表、代码块视觉层级。
- [ ] AC-14.2：四种内容类型均遵循 `content-template.md` 定义的固定分节骨架。
- [ ] AC-14.3：新增依赖（react-markdown、remark-gfm）在 plan 阶段声明理由并通过人工审查（宪法 1.3）。
- [ ] AC-14.4：存量纯文本内容可被幂等脚本迁移为结构化 Markdown。

## 3. 不做什么（范围边界）

- 不做订阅：不设订阅商品、订阅订单、订阅权益。
- 不做内推、求职匹配、招聘岗位/企业职位列表。
- 不做用户公开社区、发帖、评论。
- 不做收藏、学习进度等个性化状态。
- 不做 AI 模拟面试、自动答题批改。
- 不做 App 与小程序；本期仅 Web 阅读站 + Web 管理后台。
- 不开放用户投稿/UGC 内容发布；内容仅管理员录入/迁移。
- 不建用户侧完整账号/角色体系；访客保持匿名。
- 不采集用户级浏览行为；仅保留内容浏览数与站点 PV 等聚合统计。
- 不自动物理删除内容。
