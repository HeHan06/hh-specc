# 方法论
遇到序列决策问题（例如股票买卖、背包、编辑距离等），请按以下步骤思考：

1. 定义“状态”：从问题描述中找出影响后续决策的唯一变量。在股票题中，唯一影响后续决策的就是“是否持有股票”（因为持有则不能再买，不持有则可买）。状态越少越好。

2. 列出每天可以做的“动作”：买、卖、什么都不做。这些动作会改变状态或获得收益。

3. 写出状态转移：对于每个状态，考虑所有可能的动作，从中选最优。

4. 确定初始状态和答案：起点状态（第一天）和终点状态（最后一天不持有）。

5. 优化存储：如果转移只依赖前一步，可以用滚动变量。

这套方法论适用于绝大多数 DP 题，包括背包（状态是“当前容量”）、打家劫舍（状态是“当前房屋是否被盗”）、最长公共子序列（状态是“两个指针位置”）等。

# 常见误区提醒
- 不要试图枚举交易对：无限次交易的组合数是指数级的，必然超时。

- 不要以为手续费只在买入时扣：本质上在买入或卖出时扣一次都一样，但必须在转移中体现。

- 状态定义必须清晰：写代码前先确认 cash 和 hold 的含义，避免混淆。
