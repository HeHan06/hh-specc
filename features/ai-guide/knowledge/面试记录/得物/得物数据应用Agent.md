## 三、不足之处 + 标准口述答案

### 不足 1：算法题未写出来（图拓扑相关）

**复盘**：图拓扑题绝大多数落在「拓扑排序 / 有向图环检测」这一家族，核心是 Kahn 算法（BFS 入度法）或 DFS 三色标记法。需掌握到「不看笔记能 5 分钟内手写」的程度。

**标准解法（Java，Kahn 算法 / 入度法）**：

```java
// LeetCode 210 课程表 II：返回一个拓扑排序结果，有环则返回空
public int[] findOrder(int numCourses, int[][] prerequisites) {
    // 1. 建邻接表 + 入度表
    List<List<Integer>> adj = new ArrayList<>();
    int[] indegree = new int[numCourses];
    for (int i = 0; i < numCourses; i++) adj.add(new ArrayList<>());
    for (int[] p : prerequisites) {          // p = [后置课程, 前置课程]
        adj.get(p[1]).add(p[0]);             // 前置 -> 后置
        indegree[p[0]]++;
    }

    // 2. 入度为 0 的节点入队
    Deque<Integer> queue = new ArrayDeque<>();
    for (int i = 0; i < numCourses; i++) {
        if (indegree[i] == 0) queue.offer(i);
    }

    // 3. BFS 出队，依次"删点减入度"
    int[] result = new int[numCourses];
    int idx = 0;
    while (!queue.isEmpty()) {
        int cur = queue.poll();
        result[idx++] = cur;
        for (int next : adj.get(cur)) {
            if (--indegree[next] == 0) queue.offer(next);
        }
    }

    // 4. 数量不足说明存在环
    return idx == numCourses ? result : new int[0];
}
```

**DFS 三色标记法（环检测）要点**：`0=未访问、1=访问中、2=已完成`；遍历时若遇到 `1` 说明成环，遇到 `2` 跳过。两种方法复杂度都是 O(V+E)。

**口述话术（把算法题和岗位关联，变失分为加分）**：

> 「这道题本质是拓扑排序，用 Kahn 入度法就能解：统计入度、入度为 0 的入队、依次出队把邻接点入度减一，最后结果数不等于节点数就说明有环。其实这类 DAG 依赖问题在数据场景很常见——数据血缘的上下游依赖、任务调度的执行顺序、指标之间的派生依赖、SQL 表依赖解析，都要用同样的思路做环检测和排序。我之前做评测体系时处理数据回流链路，也是先梳理依赖关系再串流程，思路是一致的。」

**复盘**：这是岗位匹配的硬伤，但不能被动承认，要用「承认 + 迁移 + 补课 + 落地价值」四步把话接住，把「没做过」翻译成「能快速上手且带来独特价值」。

>
> 第一，数据应用 Agent 的本质还是 Agent，而 Agent 工程恰恰是我的强项。我在架构设计、上下文工程、工具路由、评测体系上有完整的从 0 到 1 经验——日均 30w 对话、工具路由准确率 97%、参数提取准确率 96.6%、单次 Token 从 70k 压到 1.5k。这些方法论是数据侧团队通常比较缺的，可以直接迁移到数据查询 Agent 上。
>
> 第二，数据侧我其实有基础和感觉。我常年用 MySQL、Redis、Kafka，还搭过数据回流机制、评测数据集管理和指标体系建设（工具路由、参数提取、人机一致率这些口径都是我定义和对齐的）。数据应用 Agent 最难的两块——指标口径一致性、LLM 生成 SQL 的幻觉——我在评测体系里做的『幻觉评估』和『人机一致率从 40% 提升到 90% 的校准』是直接对应的经验。
>
> 第三，数仓领域知识我理解其本质并有快速学习能力。数仓分层 ODS/DWD/DWS/ADS、维度建模的星型/雪花模型、事实表和维度表、指标口径的原子/派生/复合指标，本质都是『把业务问题映射到规范化数据模型』，这和我做 Agent 时『意图识别 → 参数提取 → 工具路由』是同构的映射问题。给我一个数仓环境，我能在一两周内把维度建模和指标口径吃透，并把它和 Agent 工程结合起来。
>
> 总结一句：这个岗位要的是『Agent + 数据』复合能力，我在 Agent 侧是强项，数据侧有基础和学习能力。如果让我补，最快能产出价值的不是从零学数仓，而是把 Agent 的评测和路由方法论落到数据应用场景，这是我这个背景能带来的独特价值。」
