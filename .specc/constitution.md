## 第一条 技术栈锁定（不可偏离）

以下技术栈为项目唯一合法选型，生成代码与方案不得引入清单外的框架/语言/数据库：

| 端 | 技术栈 |
|---|---|
| Web 管理后台 | React 18 + JavaScript + Vite + Ant Design |
| 微信小程序 | Taro（React 语法，与后台共享 `shared/` 层代码） |
| 后端服务 | Java 17 + Spring Boot 3 + MyBatis |
| 数据库 | PostgreSQL |
| 双端共享 | `shared/` 目录：类型定义（JSDoc/PropTypes）、工具函数、常量、API 客户端封装 |

补充约束：
- 1.1 前端一律使用 JavaScript（不用 TypeScript 新建工程；类型约束用 JSDoc 表达）。
- 1.2 后端禁止引入 JPA/Hibernate；数据访问一律 MyBatis（XML Mapper 或注解）。
- 1.3 新增第三方依赖必须在 plan 阶段声明理由，经人工审查通过后方可引入。

## 第二条 安全红线

- 2.1 **密钥零入库**：任何 API Key、数据库密码、令牌禁止出现在代码、配置、文档中；一律走环境变量。
- 2.2 **接口必鉴权**：除登录/注册等白名单接口外，所有 HTTP 接口必须校验登录态与角色权限。
- 2.3 **参数必校验**：所有入参（路径/查询/请求体）必须做类型与边界校验，拒绝裸信任。
- 2.4 **SQL 注入防护**：MyBatis 一律使用 `#{}` 参数化占位符；禁止字符串拼接 SQL，禁用 `${}` 接收用户输入。
- 2.5 **敏感操作校验角色**：删除、结算、改价等敏感操作必须二次校验操作者角色与数据归属。
- 2.6 **密码与凭证**：密码必须哈希存储（BCrypt 等），禁止明文与可逆加密。

## 第三条 测试标准

- 3.1 **测试先行**：任务顺序为 契约/数据结构 → 测试 → 实现；无测试的功能任务视为未完成。
- 3.2 后端：每个 Service 至少一个 JUnit 用例，覆盖正常路径与至少一个异常路径。
- 3.3 前端：核心业务逻辑（计算、状态流转）必须有单元测试；页面组件至少保证可渲染。
- 3.4 每个任务必须携带可执行的「验证命令」，门禁以命令执行结果为准。
- 3.5 测试失败的代码禁止进入下一阶段。

## 第四条 契约优先

- 4.1 前后端接口以 `contracts/` 下的契约文件为唯一真相源。
- 4.2 契约必须包含四要素：统一响应体、错误码、认证方式、分页约定（详见 `platform/api-conventions.md`）。
- 4.3 implement 阶段禁止私改契约；契约变更必须回到 plan 阶段重新审查。
- 4.4 双端（Web 后台/小程序）调用同一后端接口时，必须以 `shared/` 中的同一份 API 客户端封装为准，禁止各自私写请求逻辑。

## 第五条 流程纪律

- 5.1 **无 spec 不写码**：未经 specify 阶段并人审通过的需求，禁止进入实现。
- 5.2 **需求回链**：每个任务必须标注所覆盖的需求编号（Req-N）；每条需求至少被一个任务覆盖。
- 5.3 **范围边界**：规格中"不做什么"清单与实现同等重要，禁止顺手实现范围外功能。
- 5.4 **阶段门禁**：产物未通过门禁（自动检查 + 人工审查）不得进入下一阶段。
- 5.5 **人工守门**：代码进入版本库（git commit）的动作必须由人执行，specc 工作区直写、不自动提交。

## 第六条 小程序合规

- 6.1 遵守微信《小程序平台运营规范》与《微信小程序平台服务条款》：不得诱导分享、不得虚拟支付违规类目、内容合规。
- 6.2 收集用户个人信息必须在 `app.json`/隐私接口中声明隐私协议，遵循最小必要原则。
- 6.3 登录态打通：小程序端使用微信登录（code2session）换取系统令牌，与后台 JWT 体系对齐（详见 `platform/api-conventions.md`）。
- 6.4 包体积纪律：主包 ≤ 2MB，总包 ≤ 20MB；超出必须在 plan 阶段给出分包方案。
- 6.5 涉及支付、手机号等敏感能力，必须在 spec 中显式标注类目与资质要求。

## 第七条 规范基线（代码 + 契约 + 文档）

最上层原则：**任何一条规范、契约、平台知识，只允许存在一份源文件；其它文档对它的引用一律沿用「文档相对路径」引用，禁止复制粘贴其内容。** 凡被引用的文件必须先存在；引用方与源文件的冲突，以源文件为准（对应于"单一真相源 / DRY 思想，禁止重复造轮子"）。

- 7.1 命名：前端组件 PascalCase、函数/变量 camelCase；后端类 PascalCase、方法/变量 camelCase、常量 UPPER_SNAKE。
- 7.2 注释：代码注释使用中文；注释解释"为什么"，不复述"是什么"。
- 7.3 错误处理：后端统一异常处理返回标准响应体；前端统一拦截器处理错误码，禁止静默吞错。
- 7.4 日志：后端关键操作（下单、结算、权限变更）必须记录操作日志（谁、何时、对什么数据、做了什么）。
- 7.5 禁止提交：调试输出（console.log 残留、System.out 调试）、注释掉的死代码、TODO 占位实现进入 verify。

## 第八条 宪法效力

- 8.1 本宪法由 M5 上下文组装器在**所有阶段**强制注入，不可被阶段指令覆盖。
- 8.2 阶段指令、模板、平台层知识如与本宪法冲突，以本宪法为准，并应立即修订冲突文档。
- 8.3 宪法条款的豁免必须经人工书面批准并记录于版本历史，禁止隐式豁免。
