# 平台层知识：Web 管理后台规范（web-admin-standards）

> 层级：平台层 ｜ 用途：plan / implement（web-admin 任务）/ verify 阶段注入
> 目标：生成的后台代码遵循统一的管理系统模式，可维护、权限清晰

## 1. 权限模型（RBAC）

- 1.1 后台一律采用基于角色的访问控制：用户 → 角色 → 权限点。
- 1.2 权限点粒度到「菜单/页面」与「操作」（增删改审）两级。
- 1.3 前端做菜单/按钮级显隐（体验），后端做接口级校验（安全）——**后端校验是强制项，前端显隐不可替代后端校验**（对应宪法 2.2/2.5）。
- 1.4 路由守卫统一处理未登录/无权限跳转，禁止各页面私写。

## 2. 页面标准模式

管理系统页面收敛为以下模式，生成代码优先套用：

| 模式 | 组成 | 适用 |
|---|---|---|
| 列表页 | 查询表单 + ProTable/表格 + 分页 + 操作列 | 绝大多数管理页面 |
| 详情/编辑页 | 表单（Ant Design Form）+ 校验规则（复用 shared/）| 新建/编辑 |
| 仪表盘 | 统计卡片 + 图表 | 首页/报表 |

- 2.1 表格列定义、查询参数、分页参数与后端契约严格对齐（分页格式见 `platform/api-conventions.md`）。
- 2.2 表单校验规则尽量定义在 `shared/`，双端复用；提交前二次校验。
- 2.3 删除等危险操作必须二次确认（Popconfirm/Modal）。

## 3. 状态与数据流

- 3.1 服务端状态用数据请求层统一管理（加载/错误/刷新），不在组件内散落。
- 3.2 全局少量状态（登录用户、权限点）用 Context；避免为小需求引入重型状态库。

## 4. 交互与反馈

- 4.1 所有异步操作有加载态与结果反馈（成功 message / 失败提示错误码文案）。
- 4.2 错误码文案映射统一放 `shared/`，禁止页面内硬编码错误文案。

## 5. 工程规范

- 5.1 目录结构遵循 `platform/tech-stack.md` 第 2 节约定。
- 5.2 接口封装统一走 `shared/` API 客户端，页面不直接裸写 fetch/axios。
- 5.3 关键业务逻辑（计算、状态流转）抽到 `shared/` 并配单元测试（对应宪法 3.3）。
