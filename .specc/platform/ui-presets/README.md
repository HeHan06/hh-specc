# 平台层知识：UI 预设库（ui-presets）

> 层级：平台层 ｜ 用途：**plan / implement 阶段注入，锁定一个需求的视觉与布局范式**
> 目标：让 AI 生成的 UI「不靠审美靠范式」——同一需求所有页面都从同一套已验证的布局骨架 + 设计令牌长出，杜绝「每次 AI 自由发挥、首页一个样列表另一个样」。
> 性质：**硬性约束**。被选中的预设 = 该需求前端的视觉宪法；其令牌 + 骨架 + 纪律在 plan/implement 注入给引擎。

## 一个预设 = 什么？

一个预设不是一个「配色方案」，而是**一个产品类型对应的、已被市场验证的完整页面范式**。每个预设目录含两个文件：

| 文件 | 作用 |
|---|---|
| `README.md` | 文字权威源：愿景 + 设计令牌 + 布局骨架 + 组件纪律（plan/implement 注入的唯一源） |
| `preview.html` | 视觉图：用该令牌渲染的典型页面示意（纯静态 HTML），`ui <ID> list` 时在浏览器展示供「看图确认选型」 |

> UI 选型主观，**必须先看视觉图再定**，不能只看文字描述。视觉图是预览资产，不参与引擎注入；令牌/骨架以 `README.md` 为准（FRAMEWORK-DEV §1.2）。

`README.md` 内部按三块组织：

| 块 | 作用 | 回答的问题 |
|---|---|---|
| ① 愿景 + 适用场景 | 一句话说明 + 什么时候用它/不用它 | 这个范式做给谁？ |
| ② 设计令牌 | 色板/字号/间距/圆角/阴影（唯一权威源） | 视觉长什么样？ |
| ③ 布局骨架 + 组件纪律 | 标准页面结构 + 用哪些组件 + 反模式 | 页面怎么搭？ |

> 设计令牌是**唯一权威源**：所有页面取值只准来自它，禁止硬编码颜色/字号/间距。

## 一个需求怎么用预设？

```bash
./specc.sh ui <需求ID> list            # 列出可用预设，并在浏览器打开各预设视觉图（preview.html）
./specc.sh ui <需求ID> select <code>   # 看图确认后，锁定一个预设 → 写入 features/<ID>/contracts/ui-preset.md
```

选中后，plan/implement 阶段把该预设文件（含愿景/令牌/骨架三块）注入给引擎，作为该需求前端的**视觉与布局契约**。

## 预设怎么选？（你只做选择题）

- 管理后台 / 数据看板 → `dashboard-admin`
- C 端营销 / 品牌官网 → `landing-page`
- 移动端内容流 / 小程序 → `mobile-content-feed`

## 与其它契约的关系

- **与 `frontend-architecture.md` 的关系**：前者管「代码分层形态」（F-01~F-06，页面→service→api→shared），本库管「视觉与布局范式」。两者正交：**选哪个预设不影响分层，分层永远遵守 F-01~F-06**。若冲突，以 `frontend-architecture.md` 契约为准。
- **与 `tech-stack.md` 的关系**：技术选型（Ant Design / Taro / Vue 等）由 tech-stack 锁定，预设**只在其组件库之上描述如何组织页面**，不引入新依赖。

## 单真相源约束（宪法 7.6）

本库的每个预设是一个**独立源文件单位**，其它文档（spec、plan、contracts）对它的引用只允许「选指路径」，禁止复制其令牌/骨架内容。
