# 平台层知识：小程序平台规范（miniprogram-standards）

> 层级：平台层 ｜ 用途：plan / implement（miniprogram 任务）/ verify 阶段注入
> 目标：生成的小程序代码符合微信平台规则，能通过审核并合规运营

## 1. 平台合规（对应宪法第六条）

- 1.1 遵守微信《小程序平台运营规范》：不诱导分享/关注、不做虚假宣传、内容合法合规。
- 1.2 类目匹配：功能必须与所申请服务类目一致；涉及支付、直播、医疗、金融等特殊类目需先确认资质，并在 spec 中显式标注。
- 1.3 虚拟支付：iOS 端虚拟商品支付受限，涉及虚拟商品交易的功能必须在 plan 阶段说明合规方案。

## 2. 隐私与用户信息

- 2.1 收集任何用户信息前，必须通过 `wx.getPrivacySetting` / 隐私协议弹窗获得授权。
- 2.2 遵循最小必要原则：能用 openid 就不采集手机号；采集手机号需使用微信手机号快速验证组件。
- 2.3 隐私接口（地理位置、相册、相机等）必须在 `app.json` 的 `permission` / `requiredPrivateInfos` 中声明。
- 2.4 用户信息不得在日志中明文输出。

## 3. 登录态（与后端打通）

- 3.1 流程：`wx.login` 获取 code → 后端 `code2session` 换取 openid/session_key → 签发系统 JWT → 后续请求携带。
- 3.2 session_key 严禁下发到前端；令牌刷新机制由契约统一定义（见 `platform/api-conventions.md`）。
- 3.3 未登录访问受保护接口时，统一跳转登录/授权流程，不得静默失败。

## 4. 包体积与性能

- 4.1 主包 ≤ 2MB，总包 ≤ 20MB；超限必须分包（独立页面/低频模块拆分包）。
- 4.2 图片资源优先走 CDN，不打包进小程序；单张图片压缩后再使用。
- 4.3 避免在 `onLoad` 中串行发起多个请求，可并行的并行、有依赖的说明依赖。

## 5. 工程规范（Taro）

- 5.1 页面路由在 `app.config.js` 集中声明；tabBar 页面按微信规范配置。
- 5.2 微信特有 API（`wx.*`）统一封装在 `src/platform/`，页面中不裸调，保证可测试与可替换。
- 5.3 组件优先函数组件 + Hooks；跨端差异逻辑走 `shared/` 接口 + 小程序适配实现。
- 5.4 错误上报：接口错误与运行时错误统一上报入口，不得静默吞错（对应宪法 7.3）。

## 6. 审核常见驳回点（生成代码时主动规避）

- 页面存在明显测试数据/占位文案
- 功能不完整（点击无响应的入口）
- 隐私协议缺失却采集信息
- 类目与实际功能不符
